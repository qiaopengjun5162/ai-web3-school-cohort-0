# 2026-06-01 钱包与权限（Wallet / Permission）

**今日学习内容：**

- Agent 不应该拥有"钱包"，只应该拥有一组可限制、可审计、可撤销的能力
- AI Wallet UX 的核心：让用户知道 Agent 正在做什么、为什么这么做、下一步会发生什么
- Permission Policy 是写给执行层的规则，必须能被程序检查，不能靠模型自觉
- AI 可以生成 policy 草稿，但最终执行必须由 wallet、smart account、guard 或合约模块校验
- Session Key 适合低风险、高频、可限额的短期任务
- Guard 在交易执行前做确定性规则检查，灰区交人工确认
- ERC-4337 的关键价值是让 Agent 使用可编程 Smart Account
- Pre-transaction Simulation 是 Agent 钱包安全基础
- Recovery / Revocation：给了 Agent 权限就必须设计撤销路径
- 没有权限层，Agent 只能停留在建议层；权限层做错，又会直接威胁资产安全
- 靠谱产品按风险逐步开放权限：只读 -> 草稿+人工签名 -> 小额白名单 session key -> 复杂自动化+guard+审计+撤销

**今日收获总结：**
Agent 的钱包问题不是"私钥保管"问题，而是"能力边界"问题。Permission Policy 必须是确定性的、可审计的、可撤销的。Session Key + Guard + Pre-transaction Simulation 才是把"建议"变成"可控执行"的关键。
